PreTest

  1. Tujuan menggunakan version control dalam pengembangan perangkat lunak
  2. Perbedaan git add dan git commit
  3. Cara membuat branch baru di Git

    4. 1. Tujuannya:

    1. Melacak riwayat perubahan: bisa tahu siapa mengubah apa, kapan, dan kenapa.
    2. Mengembalikan versi lama jika terjadi kesalahan atau bug.
    3. Memudahkan kerja tim: banyak orang bisa mengerjakan proyek yang sama tanpa saling menimpa pekerjaan.
    4. Mengembangkan fitur secara terpisah melalui branch tanpa mengganggu kode utama.
    5. Menjadi cadangan (backup) kode, terutama jika disimpan di repository online seperti GitHub.

2. perbedaan

git add memlilih file yang akan disimpan sedangkan git commit adalah meyimpang ke riwayat

3. branch baru

  • git checkout -b nama-branch

PostTest

  1. Fungsi git merge
  2. Cara mengatasi konflik saat merge
  3. Menambahkan file baru ke repository dan commit
  1. git merge menggabungkan perubahan dari satu branch ke branch lain, biasanya fitur yang sudah selesai ke branch utama (main). Dengan begitu, pekerjaan yang dilakukan terpisah di beberapa branch bisa disatukan tanpa menghilangkan riwayat commit.
  2. 1. Jalankan git merge nama-branch. Git akan memberi tahu file mana yang konflik. 2. Buka file tersebut. Kamu akan melihat penanda seperti ini:
    <<<<<<< HEAD kode dari branch saat ini ======= kode dari branch yang digabung >>>>>>> nama-branch
    3. Edit manual: pilih salah satu versi atau gabungkan keduanya, lalu hapus penanda <<<<<<<, =======, dan >>>>>>>.
    4. Tandai konflik sudah selesai: git add nama-file
    5. Selesaikan merge: git commit
    • Masuk ke folder repository: cd nama-folder
    • Buat atau salin file baru ke folder tersebut.
    • Cek status: git status
    • Tambahkan file ke staging area: git add nama-file (atau git add . untuk semua file)
    • Commit: git commit -m "Menambahkan file baru"
    • (Opsional) Kirim ke GitHub: git push origin main
